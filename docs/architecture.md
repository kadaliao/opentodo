# 架构

## 客户端（`app/`）

本地优先：所有读写都先落到本机 SQLite，界面直接订阅数据库的变化；联网时再由同步引擎和服务器交换改动。没网、服务器挂了，应用照样能用。

| 层 | 位置 | 说明 |
|---|---|---|
| 数据 | `lib/data/db.dart` | drift 表定义：清单 `TaskLists`、任务 `Tasks`、子任务 `ChecklistItems` |
| 仓库 | `lib/data/repo.dart` | 所有写操作的唯一入口，负责打同步标记 |
| 领域 | `lib/domain/` | 纯函数，单测覆盖：日期标签、快速添加解析、视图分组 |
| 状态 | `lib/state/providers.dart` | Riverpod：数据库流、当前视图、选中任务、每分钟刷新的时钟 |
| 界面 | `lib/ui/` | 宽屏三栏（≥1000）、中屏两栏（≥640，详情另开一页）、手机单栏加抽屉 |

### 数据约定

- **ID** 用 UUID v7（按时间有序），客户端离线生成，不依赖服务器。
- **每张表都有同步字段**：`createdAt`、`updatedAt`（毫秒）、`deletedAt`（删除标记，非空即已删除，行本身保留到服务器确认）、`serverVersion`（服务器给的版本号，0 表示从未同步）、`dirty`（本地有未推送的改动）。仓库的每次写入都会更新 `updatedAt` 并置 `dirty`。
- **日期是“浮动”的日历日期**：`dueDate` 存 `YYYY-MM-DD` 字符串，`dueTime` 存当天第几分钟（为空表示全天）。出差换时区时，18 号的任务仍在 18 号。`timeZone` 字段先留着，给以后“固定时刻”的提醒用。
- **时间段**存在 `duration`：从开始（`dueDate` + `dueTime`）到结束的分钟数，结束不含。全天的时间段是整天数，`2880` 是到期那天和第二天；只占一天、或者只是一个时刻的任务为空。开始仍然是 `dueDate` / `dueTime`，所以排序、提醒（相对开始）、重复都不用改；结束靠加分钟算，和日期一样按墙上时间浮动。时间段在它覆盖的每一天都算“在那天”：“明天”列出覆盖明天的任务，“今天”“最近7天”里已经开始的放在今天这一组；过期看结束（有时间的到结束那一分钟，全天的过了最后一天）。拖动时整段一起移动；有时间和全天之间切换时，全天保留覆盖的天数，变回有时间则清掉。函数在 `lib/domain/dates.dart` 的“spans”一节。
- **提醒**存在任务行的 `reminders` 里，是一组分钟数（JSON 数组），相对任务的到期时刻：有时间的任务是那个时间，全天任务是当天 0 点；负数表示之前，和 iCalendar 的 `TRIGGER` 同义。所以 `0` 是准时、`-30` 是提前 30 分钟；全天任务的 `540` 是当天 9:00、`-900` 是前一天 9:00。提醒和日期一样跟着设备时钟浮动。清除日期会连带清掉提醒和重复。
- **重复**存在 `repeatRule`，是 iCalendar RRULE 的子集（`FREQ=WEEKLY;BYDAY=MO,WE`、`FREQ=MONTHLY;BYDAY=-1FR`、`UNTIL`、`COUNT`），规则没写的部分（周几、几号）取任务当前的日期，相当于 DTSTART。`repeatFrom` 区分按到期日期（0）还是按完成日期（1）算下一次。`COUNT` 表示“含这一次还剩几次”，每完成一次减一。另有两种中国特有的：农历用 RFC 7529 的 `RSCALE=CHINESE`（`RSCALE=CHINESE;FREQ=YEARLY;BYMONTH=8;BYMONTHDAY=15;SKIP=BACKWARD` 是农历每年八月十五），法定工作日是周一到周五加上 `X-HOLIDAYS=CN`（`FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;X-HOLIDAYS=CN`），旧版本应用读成普通的工作日。见下面“节假日和农历”。
- **收集箱**不是一行数据，而是固定的 `listId = 'inbox'`。
- **垃圾桶和删除是两回事**：`trashedAt` 是放进垃圾桶，可以恢复；`deletedAt` 是永久删除，留作同步的删除标记。
- **标签**以 JSON 数组存在任务行里（`["工作","出行"]`），同步时跟着任务走，不需要单独的关联表。

### 重复任务的完成

重复任务只有一行。完成它时，这一行不关闭，而是把日期挪到下一次，同时留下一份已完成的副本（没有提醒和重复）给“已完成”列表，子任务清空勾选给下一次用。

- 下一次是“晚于原日期、也晚于今天”的第一个日期：过期好几天的每日任务完成后到明天，不会再留一个过期的。按完成日期时，从今天重新起算。
- 副本的 ID 由任务 ID 和这一次的日期算出来（UUID v5），子任务副本同理。两台设备离线时都完成了同一次，同步后只有一份；撤销留下的删除标记，再完成时会被同一 ID 覆盖回来。
- 最后一次（`UNTIL` 到了或 `COUNT` 用完）完成时，任务正常关闭。“跳过此次”只挪日期、不留副本；跳过最后一次等于放弃（`status = wontDo`）。
- 列表里只显示当前这一次，不展开未来的重复；日历里会显示以后的日期（见“日历”）。

逻辑在 `lib/domain/recurrence.dart`（纯函数）和 `TaskRepo.setCompleted` / `skipOccurrence` / `undoRepeatCompletion`。

### 提醒的调度

`lib/state/reminder_providers.dart` 的 `ReminderController` 在任务变化（防抖 0.5 秒）、回到前台、每 15 分钟时，用 `upcomingReminders` 算出接下来最近的 48 个提醒（iOS / macOS 系统最多替应用保留 64 个待发通知），交给 `ReminderScheduler` 和系统里已排上的比对：只取消变了或不要了的、只新排缺的。通知 ID 由任务 ID 和触发分钟算出，同一个提醒反复调度不会重复。已经弹出的通知不动。

- iOS / macOS / Android 由系统定时（`flutter_local_notifications`），应用没开着也会弹。时间按“那一刻”交给系统（UTC），时区变了靠应用回前台时重排。
- Windows / Linux 插件没有定时能力，应用开着时用计时器到点弹出。
- 权限在第一次真有提醒要排时才申请；被拒后日期对话框里提示“去开启”，回到前台会重新检查。
- 点通知：`openTaskRequestProvider` 记下任务，首页切到能看到它的视图并选中（窄屏打开详情页）。被通知唤起时同样处理。
- 已知限制：任务在别的设备上完成后，这台设备要等应用运行、同步之后才会取消它的提醒；应用一直没开的话，到点仍会弹。

#### 通知上的按钮

通知带“完成”和“稍后提醒”两个按钮（`lib/notify/reminder_actions.dart`）。iOS / macOS 用通知分类（初始化时登记一次，通知上写分类名），Android / Linux 直接写在通知上；Windows 没加。

- 完成：任务没完成、没删时把它勾掉，重复任务照常挪到下一次（和列表里勾选一样，`TaskRepo.setCompleted`），同时去掉它的稍后提醒。
- 稍后提醒：过“设置 → 稍后提醒”的时间（出厂 15 分钟）再提醒一次。稍后提醒存在本机 `KeyValues` 的 `reminders.snoozed`（任务 ID → 时刻），不同步；`upcomingReminders` 把它们和任务自己的提醒一起排，所以调度器比对时不会把它当多余的取消。过了时间的在下一次调度时清掉。
- 谁来处理：macOS 和 Linux 总是交给应用的主 isolate（应用没开就先启动它，按钮记在启动信息里）。iOS 和 Android 上按钮不打开应用，插件另起一个后台引擎跑 `reminderActionInBackground`：应用在运行时（主 isolate 用 `IsolateNameServer` 登记了端口）只把按钮转给应用处理，界面马上跟着变；应用没在运行时自己打开数据库、执行、再按数据库重排系统通知（不申请权限，能按按钮说明已经允许）。两个连接可能同时开着同一个数据库文件，所以打开时设了 `busy_timeout`。
- 交给系统的通知样子变了（比如加了按钮），把 `reminder_providers.dart` 的 `_reminderFormat` 加一：下次调度时把系统里已排上的全部换掉，老通知也有新按钮。

### 节假日和农历

两份数据都打包在应用里，不联网。

- **法定节假日和调休**（`lib/domain/holidays.dart`）：照抄国务院办公厅每年的《关于××××年部分节假日安排的通知》，每个假期写放假的起止日期和调休上班的日子。现在有 2025–2027 年。`holidayOn` 说某天是“休”还是“班”，`isWorkday` 判断是不是工作日（没数据的年份按周一到周五）。每年 11 月前后新通知出来后要加一年再发版，步骤见开发文档。
- **农历**（`lib/domain/lunar.dart`）：1900–2100 年每个农历年一个整数，记正月初一离 1 月 1 日几天、闰几月、各月大小。这张表由 `app/tool/lunar_table.swift` 用 macOS 自带的中国历（ICU，北京时间）生成，测试里有一批同样从 macOS 取来的日期对照。提供公历↔农历换算、月名日名（正月、闰六月、廿三）、传统节日（春节、元宵、端午、七夕、中秋、重阳、腊八、除夕）。

用在三处：

- 重复：法定工作日跳过放假、加上调休上班的周末（`RepeatRule.chinaHolidays`）；农历每年 / 每月（`RepeatRule.lunar`），农历每月把闰月也算一个月，农历每年只落在非闰月。某个月没有三十就落在廿九（`SKIP=BACKWARD`），所以“农历每年腊月三十”总是除夕。日期对话框的重复菜单有“法定工作日”“农历每年（八月十五）”“农历每月（十五）”，自定义重复里有“按农历”和“按法定节假日调休”。
- 快速添加：“每个法定工作日”“每年农历八月十五”“农历每月初一”“每年除夕”，以及一次性的“农历八月十五”“除夕”（下一个这样的日子）。
- 日历：月视图格子和日 / 周视图的表头在日期旁边写农历日（初一写月名）或节日名，放假的标“休”、调休上班的标“班”；“更多”里可以关掉（`CalendarPrefs.showLunar`）。

### 设置和任务默认值

设置在 `lib/state/settings_providers.dart`（`AppSettings`），存在本机 `KeyValues` 的 `settings`（JSON），不同步；读不出来或字段不认识时用默认值。入口：电脑上左侧图标栏最下面的齿轮，手机上抽屉里的“设置”。

任务默认值（`lib/domain/task_defaults.dart` 的 `TaskDefaults`）：有时间的任务的默认提醒（出厂是准时）、全天任务的默认提醒（出厂是无）、时间段的默认时长（出厂 1 小时）。任务“新有了日期或时间”时用上：快速添加（含日历里的新建框）、右键菜单第一次给任务设日期（`TaskRepo.setDue`）、日期对话框给没日期的任务打开时、对话框里或日历拖动在有时间和全天之间切换时（`TaskRepo.moveTo`）。已经有提醒的任务改日期不动它的提醒。`TaskRepo` 通过构造时传入的 `defaults` 函数读当前值，测试里可以换掉。

### 快速添加

`lib/domain/quick_add_parser.dart` 把一行输入拆成标题、日期、时间、标签、优先级，并返回每段识别文字的位置，供输入框高亮。支持：今天/明天/后天/大后天、今晚/明早、周X/下周X/这周X/下下周X、周末、N天后/N周后、X月X日、X号、M/D、YYYY年M月D日；上午/下午/晚上/中午/凌晨 + X点/X点半/X点一刻/X:XX、3pm；`#标签`、`!高 !中 !低`。没写上下午时，1–6 点按下午算。一周从周一开始。

时间段：开始的时间后面跟“到 / 至 / - / ~”和结束时间，“下午3点到5点”“15:00-16:30”“3pm-5pm”；结束没写上下午时取开始之后最近的那个（“上午11点到1点”到 13:00），早于开始就算到第二天（“晚上10点到凌晨2点”）。

重复：每天/每N天、每周X（可以连写“每周一三五”“每周二、四”）/每周/每N周、每个工作日、每周末、每月N号/每月最后一天/每月/每N个月、每年M月D日/每年。一定要带“每”字，免得“工作日志”这类词被误认。没写日期时从第一次出现的那天开始；写了时间而今天那个时间已过（“每天早上8点”在 10 点输入），从下一次开始。有时间的任务自动带一个准时提醒。

### 日历

日历是和任务并列的模块：电脑上窗口最左边一列图标切换（`home_shell.dart` 的 `_ModuleRail`），手机上是底部导航栏。当前模块在 `moduleProvider`，切换时清掉选中的任务。

- 模式（`domain/calendar.dart` 的 `CalendarMode`）：日、3 天、周、月、日程。每个模式由“锚点日期”（`calendarAnchorProvider`）算出要显示的日子（`visibleRange`）：周和月从周一开始，月视图补齐整周；日程是锚点所在的月，当月从今天开始往后列。上一页 / 下一页按模式移动锚点，按月翻时尽量保留几号（1 月 31 日 → 2 月 28 日）。
- 显示什么（`calendarEntries`，纯函数）：有日期、没进垃圾桶、所在清单没被隐藏的任务；已完成的可以隐藏。重复任务除了它自己的日期，还会在以后的日期上显示成“预计”的条目（`projected`），用 `recurrence.dart` 的 `occurrencesAfter` 逐个算，遵守 `COUNT` 和 `UNTIL`。预计的日期都在今天以后：过期的重复任务完成时会跳过已经过去的日子（见上一节），按完成日期重复的从今天重新算。预计条目不能勾选、不能拖，点开是任务本身。
- 时间格（日、3 天、周）：每小时 48 像素。时间段按实际长度画，跨过午夜的分成每天一截；只有一个时刻的任务按 30 分钟画。时间重叠的并排分列（`layoutTimed`，每个任务放进第一个空出来的列；不到 30 分钟的也按 30 分钟占位，因为画出来不会更矮）。没有时间的任务在顶上的“全天”一栏。跨几天的任务（全天的时间段、跨午夜的）在每一天都有一个条目（`CalendarEntry.dayIndex` 区分第几天），重复的时间段也一样。
- 拖动改期：电脑上直接拖，手机上长按再拖（不和滚动抢手势）。月视图里拖到别的格子只改日期；时间格里按落点改日期和时间，吸附到 15 分钟；拖进“全天”去掉时间。时间段整段移动：拖它的第二天到周五，开始就挪到周四（`dropTarget`）。都走 `TaskRepo.moveTo`：在有时间和全天之间切换时提醒重新开始（有时间的给“准时”，全天的清空），和日期对话框一致，因为提醒是相对到期时刻存的。
- 改结束时间：时间格里拖任务的下边缘，吸附到 15 分钟（`TaskRepo.setDuration`）；没有时间段的任务这样拖就有了。
- 点空白格子新建：月视图是那天的全天任务，时间格是点到的半小时。新建框就是快速添加输入框（`QuickAddField` 的 `target`），照样识别输入里的日期，写了日期以输入的为准。
- 窄屏：手机的月视图是小月历（有任务的日子带点）加选中那天的列表；电脑宽屏有侧栏（小月历、要显示的清单、账号），点任务在右边打开详情，中屏打开详情页。
- 模式和显示选项存在本机的 `KeyValues`（`calendar.prefs`，JSON），不同步。

## 同步（M2）

服务端在 `server/`：Go，SQLite（纯 Go 驱动，不用 cgo），部署时只有一个程序文件加一个数据库文件。存储层封装在 `internal/store`，用户量上来后换 PostgreSQL 只改这一层。

| 接口 | 说明 |
|---|---|
| `POST /v1/auth/register`、`/v1/auth/login` | 邮箱 + 密码（bcrypt），返回不透明的会话令牌，服务器只存它的 SHA-256 |
| `POST /v1/auth/logout`、`GET /v1/me` | 需要 `Authorization: Bearer <令牌>` |
| `POST /v1/sync` | 推拉合一：请求带 `cursor` 和本地改动，响应带被接受的改动、新改动、新 `cursor` 和 `hasMore` |

- 每个用户有自己的递增版本号。服务器每存一条改动就给它一个新版本号；客户端记住看到的最大版本号（`cursor`），下次只拉更新的。一页最多 500 条，`hasMore` 为真就接着拉。
- 冲突按整行“`updatedAt` 新者胜”。推上来的改动比服务器上的旧时，服务器不存，并把服务器上的版本发回去，客户端用它覆盖本地。
- 客户端先应用拉回的记录、再把推送成功的行标记为已同步：服务器在存这次推送之前就读好了要发回的记录，所以发回的可能比刚推上去的旧；这时本地行还是脏的，会被保留（集成测试“the newer edit wins a conflict”覆盖这个情况）。
- 推送期间本地又改过的行，`updatedAt` 已经变了，不会被误标为已同步，下次再推。
- 删除靠 `deletedAt` 删除标记传播；服务器确认后，客户端把已同步的删除标记物理删掉。
- 已知限制：用设备时钟比较新旧，设备时间不准时可能误判；以后改成混合逻辑时钟（HLC）。

客户端在 `app/lib/sync/`：`codec.dart`（逐字段的网络格式，旧客户端能读新字段）、`sync_engine.dart`（一次同步）、`account.dart`（登录接口和错误文案）；调度在 `app/lib/state/sync_providers.dart`。账号、令牌和同步进度存在本地的 `KeyValues` 表里，不参与同步。
